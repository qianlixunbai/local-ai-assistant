## Root Causes

- 普通分段 record 共享 anchor 完成标记，导致部分失败被成功 sibling 隐藏；旧插入位置也逆转译文顺序。
- popup preflight 与 content session 使用不同生命周期，原有 content generation 无法取消 popup 的旧 await。
- 旧记录只确认 DOM 尚存在，没有确认源文本与段落范围仍属于本次请求；observer 也没有覆盖源文本替换与 characterData。
- 选区消息没有 frame / document 目标。iframe 注入后 popup 的广播消息也必须明确限制到 frame 0。
- visibility 缓存跨扫描存在；普通文本只看 anchor 可见性；协议 Number(id) 转换与原始 error body 转发过于宽松。

合法旧文本 A 的响应可保留在当前 session 的文本缓存中，但插入必须通过当前源身份校验。
Restore / LAT_RESET 作废 session，旧 session 响应不写缓存。重新注入前已有的 orphan 译文保守沿用已有标记。

## B13 — Visible Sidebar / Nested Scroll Container

### Confirmed root cause

2026-10-01 读取 [MDN Introduction](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Introduction)
当前 HTML，确认 `Grammar and types` 的祖先链包含：
`a → li → ol → details → li → ol → div.left-sidebar__content → nav.left-sidebar → aside.layout__left-sidebar`。

根因：`PRUNE_SELECTOR` 过早排除 `nav` / `aside` / `role=navigation`，导致全文 collect 根本不创建 sidebar records。
修改前 `config.js` 的 `pruneSelectors` 包含 `nav`、`aside`、`[role='navigation']`。
`collectRecords()` 的 `if (PRUNE_SELECTOR && parent.closest(PRUNE_SELECTOR)) continue;`
在 visibility、BR / anchor、viewport priority、batch 之前排除该源文本。TreeWalker 会访问这些文本，
但不会创建 record。不是 iframe、模型、background 或 Ollama 链路故障。
主动 Selection 的 `translateSelection()` 直接将选区文本交给 cache / `requestBatch()`，
没有经过全文 prune / collect，所以同一 sidebar 的选区可以翻译。

| 候选原因 | 结论 |
|---|---|
| A selector / traversal | 直接根因是语义容器被 selector 整体 prune；不是 TreeWalker 不能访问 nav。 |
| B visibility / viewport false | 不是此次 MDN 全 sidebar 遗漏的直接原因：prune 更早发生。旧 visibleNow 只检查 CSS / box 可见性，不计算交集。 |
| C ancestor overflow clipping | 原代码没有 clipping ancestor 计算。移除 prune 后必须补过滤，防止裁掉的文字被发送。 |
| D document viewport only | 旧 getBoundingClientRect 只在 prioritizeRecords 按窗口高度排序，不限制收集，也不处理独立 scrollport。 |
| E scheduler only main | 否；优先级只改变顺序，三个 priority 都会分批处理，没有 main 区域专属 scheduler。 |
| F independent scroll catch-up | 原 watcher 只有 MutationObserver，容器 scroll 不产生 mutation；这是配套缺口，已通过 capture scroll 复用 debounce 修复。 |

### Minimal implementation and semantics

修复边界：navigation/sidebar 可参与全文翻译；补齐 nested overflow clipping visibility 和
independent scroll catch-up；hidden/editable/privacy boundary 保持。

- `config.js`：仅删除上述三个宽泛 prune 项；banner / menu / menubar / tablist / toolbar、hidden / aria-hidden 继续排除。
- `visibleNow()`：保留 native checkVisibility，启用 opacity 检查；fallback 校验 visibility 与祖先 display / opacity。
  `isVisible()` 的 WeakMap 仍在每轮 `collectRecords()` 重建（B05）。
- 新增 `textClippingBounds()`、`textIntersectsClip()`、`isCollectibleText()`：
  Text Range 的各 rect 与 document viewport、所有 relevant overflow clipping ancestor 的 client box 求交；
  overflow-x / overflow-y 分轴处理，支持 auto / scroll / hidden / clip / overlay。
  client box 排除边框和滚动条；正面积交集才收集，部分可见项可收集。几何不跨扫描缓存。
  display:contents / 非替换 inline 本身不作为 overflow box；sticky / fixed 不因 position 值被排除。
  body/html 的文档滚动不作为独立 scrollport，普通文档长正文保留原有整页收集、viewport priority 行为。
  nav / aside / navigation 即使无 overflow，也检查 document viewport。
- `collectRecords()` 与 `indexBreakSegments()` 的普通 / BR 文本都检查源 Text Range。
  BR 不以共享容器的大 rect 代替每段文字，隐藏 inline 仍被过滤（B06）。
- `sourceSnapshot()` / `matchesSourceSnapshot()` 记录裁剪状态：完成文字滚出可视区不会删除译文；
  同一 anchor 中此前被裁掉的 inline 新进入视区会作废旧聚合，再收集实际可读的新组合。
  文本 / DOM 身份、hidden、editing 与会话 generation 的校验保留。
- `startWatching()` / `stopWatching()` 注册 / 移除 document capture scroll；新增 `onContentScroll()`
  只标记 dirty 并调用现有 `scheduleDynamic()`，复用既有 debounce、single-flight 和 catchupSkipRecords。
  未主动翻译前没有自动 scroll 翻译；Restore / LAT_RESET 停止监听。没有新调度器或 IntersectionObserver。

contenteditable / plaintext-only / designMode 仍由 `isEditable()` 排除（B10）；Selection handler、
缓存 key、background、消息协议、manifest、host permissions 与 Ollama 参数均未在 B13 中改变。
